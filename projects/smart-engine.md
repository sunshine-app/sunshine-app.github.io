| 项目信息 | 内容 |
| :--- | :--- |
| **项目周期** | 2018.06 – 2019.02 |
| **我的角色** | 核心开发（数据管道 + 后端服务） |
| **核心目标** | 构建一套分布式实时监控与预警系统，实现从数据采集到可视化告警的全流程自动化 |

**技术亮点：**

- 📊 **多数据源整合**：Historian 时序数据库 + MySQL 关系型数据库混合存储
- 🖥️ **前后端分离**：Flask + Socket.IO 实时推送，ECharts 可视化展示

### 核心技术详解
	1. 数据接入管道 —— 从 Historian 到分布式存储
		属性	说明
		数据源	Historian（工厂级时序数据库）
		抽取工具	C# 定期抽取
		目标存储	KairosDB + Cassandra
		调度策略	定时任务，周期性同步
		
		存储选型考量：
			存储系统	用途	选型理由
			KairosDB	时序数据存储	专为时间序列设计，支持高效的时间范围查询
			Cassandra	分布式备份	高可用、横向扩展能力强，防止数据丢失
			Redis	缓存/消息队列	高性能内存数据库，串联各模块，降低延迟
			
	2. 数据处理 —— 清洗、特征工程与衍生指标
		属性	说明
		工具	Python（NumPy、Pandas）
		处理内容	数据清洗、质量标记、特征工程、衍生指标计算
		
		数据清洗：
			空值检测与填充（插值法、均值填充）
			异常值识别与标记
			数据质量分级标记（可靠/可疑/无效）

		特征工程：
			特征类型	计算方法	用途
			插值计算	线性插值、样条插值	填充缺失值，保证数据连续性
			移动平均	滑动窗口均值	平滑噪声，凸显趋势变化
			衍生指标	变化率、累计值、峰值	设备状态评估
			
	3. 告警生成 —— 结构化预警
		属性	说明
		触发条件	多维度规则引擎
		存储	MySQL（结构化告警信息）
		推送方式	Socket.IO 实时推送
		
		告警生成逻辑：
			对实时数据进行规则匹配
			生成结构化告警信息（时间、设备、阈值、当前值等）
			存储至 MySQL 供历史查询
			通过 Socket.IO 推送到前端
			
	4. 后端服务 —— Flask + Socket.IO
		属性	说明
		框架	Flask（HTTP 服务）、Socket.IO（实时推送）
		功能	数据请求响应、实时数据推送
		部署	Nginx 前后端分离部署
